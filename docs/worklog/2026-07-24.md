# 2026-07-24 — Support feature rethink (async front door)

## Context / problem
The "🆘 Get Support" feature was a live WebRTC screen-share + chat: clicking it
dropped the user into an iframe of the whole app and waited for an admin (Derek)
to join a Socket.IO room. Since Derek isn't sitting in `/admin/support` waiting,
users hit an **infinite "waiting for an agent" spinner** — worse than no live
option, because it promised real-time help that couldn't be delivered.

## Decision
**Async front door, opportunistic live back door — never promise live to the user.**
- Front door = a written support form. User submits, sees "Derek will get back to
  you by email, usually within a day." No spinner, no live promise.
- Live screen-share is *kept* but becomes **admin-initiated per request** (Phase 2),
  so Derek never has to decide up-front "am I open for support today" — he just
  reacts if a request catches him at a good moment.
